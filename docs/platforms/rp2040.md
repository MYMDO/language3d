# RP2040 (Raspberry Pi Pico + ST7789 240×240)

Production game firmware. The low-level ST7789/SPI driver is a proven,
working implementation — do not "refactor" it without a hardware-verified
reason.

## Display wiring (working profile)

```text
ST7789   RP2040
GND      GND
VCC      3V3
SCL      GP18
SDA      GP19
DC       GP16
RES      GP17
CS       GP15
BLK      GP20
```

Transport: SPI0, mode 0, 8-bit, MSB-first, 40 MHz, RGB565, MADCTL `0x00`,
display inversion on.

## Controls (buttons, active-low with pull-ups)

```text
W (forward)  GP2    A (strafe L) GP3
S (back)     GP4    D (strafe R) GP5
E (interact) GP6    L (language) GP7
P (progress) GP8    H (help)     GP9
```

## Build

```bash
export PICO_SDK_PATH=$HOME/pico-sdk   # Raspberry Pi Pico SDK ≥ 2.0
./tools/build-rp2040.sh
```

Artifacts land in `build-rp2040/`:

- `language3d_rp2040.uf2` — drag-and-drop flashing (primary file for users)
- `language3d_rp2040.bin` / `.hex` — alternative flashing formats
- `language3d_rp2040.elf` / `.elf.map` — debugging/development

Always build from a clean directory (`tools/build-rp2040.sh` deletes
`build-rp2040/` first) so a stale `CMakeCache.txt` can never mask a problem.

## Flash

1. Hold **BOOTSEL** while connecting the Pico over USB.
2. Copy `language3d_rp2040.uf2` onto the `RPI-RP2` drive.
3. The board reboots: display init → short red/blue checkerboard probe
   (sent through the production display path) → **game** → input active.

If you ever see a diagnostics-only image instead of the game, the firmware
is not the production target — rebuild with `tools/build-rp2040.sh`.

## Testing note

GitHub Actions verifies RP2040 compilation, linking and the presence of all
firmware artifacts on every push/PR. Display output and button input can
only be verified on real hardware and are therefore documented as manual
steps, never simulated as passing CI checks.
